# Research interests

Save the current query and filters from Search, or create a follow in Updates. All criteria are combined with AND. Text search, exact arXiv IDs, category, venue and inclusive UTC publication dates use the discovery contract. Categories match exactly; venue and complete author names ignore case. The corpus stores no stable author IDs: different people with the same name match together, and variants of a name require separate follows. This limitation is shown beside the form.

Updates checks the existing shared corpus when the page is visited without a frozen paging timestamp or when **Check for new matches** is pressed. It does not trigger external ingestion or send email. Matches are private under owner RLS, deduplicated by paper, and explain every currently matching active interest. Editing criteria filters old results immediately. Pausing hides that interest and stops checking it; resuming evaluates it on the next check. Deleting an interest removes only its match history, preserving saved papers, progress and notes.

Each interest retains the first matching time for a paper. Ordinary metadata refreshes and repeated checks do not move it. **Mark updates seen** advances a monotonic checkpoint through the displayed check, including its other pages; later matches stay new. New remains visible across visits until explicitly acknowledged, so navigation or prefetch cannot silently clear unread results. New interests start with existing matches marked new. Editing an interest preserves its history and checkpoint; papers newly matching the edited criteria become new on the next check. Historical matches returning after an edit keep their original first-match time.

Migration 0016 adds private preferences, match history and authenticated invoker RPCs. A composite owner foreign key prevents attaching results to another user's interest. Checks serialize per owner and use millisecond cutoffs for stable browser paging. Match history grows with matched corpus papers; no silent result cap is applied before matching. Display uses deterministic 40-row pages (maximum offset 100,000, matching discovery). Preferences use keyset fetching until exhausted. Criteria changes can alter a frozen page, so use a fresh check after edits.

Validation: disposable PostgreSQL tests cover frozen checkpoints, deduplication, combined filters, ambiguous author names, pause/edit/delete, paging, ownership and library preservation. Browser tests cover saving a search with a lost acknowledgement, returning after a new corpus paper, multiple matching reasons, checkpoints, edits, pause/resume, privacy and deletion.
